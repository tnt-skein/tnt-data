# Объект переноса данных

Форма одних и тех же данных описывается трижды: схемой проверки
`tnt-validate`, аннотацией `---@class` и описанием API. Три описания
расходятся молча — проверка пропускает поле, которого нет в аннотации,
а в описании API оно значится обязательным, — и ни один гейт этого
не видит: каждое описание проверяется само с собой. `tnt-data` делает
объявление формы единственным источником: из него следуют проверка
входа, выдача, аннотация и схема OpenAPI 3.0.

```lua
local data = require('tnt.data')

local User = data.define({
    name = 'User',
    fields = {
        { 'id', 'integer', min = 1 },
        { 'password', 'string', min = 12, hidden = true },
    },
})

local user, errors = User.from(request.body)   -- запись либо nil, «место → причина»
json.encode(user)                              -- выдача: без скрытого пароля
User.annotation(), User.schema()               -- аннотация EmmyLua и схема OpenAPI 3.0
```

## Зачем пакет

Из одного объявления следуют:

- **проверка входа** с приведением типов — правилами `tnt-validate`,
  с тем же видом отказа «место → причина»;
- **выдача** — только объявленные поля, без скрытых, под именами снаружи,
  со значениями Tarantool, переписанными в запись;
- **аннотация** EmmyLua записи — текстом, и сверка её с модулем;
- **схема OpenAPI 3.0** — и сверка её с документом API.

Согласие держат две сверки, и обе отвечают парой: `true` либо `nil`
и первое расхождение. Их ставят в проверки того, кто объявил форму:
поле, дописанное в объявление и забытое в аннотации или в документе,
роняет проверку, а не всплывает через полгода «неизвестным полем»
у того, кто поверил аннотации.

Зависит от `tnt-validate` (проверка), `tnt-collection` (вид таблицы в JSON,
порядок ключей) и `tnt-must` (тексты отказов). Настроек и состояния нет —
ни `configure`, ни `new`, ни `default`, ни `status`: форма — значение,
собранное объявлением.

## Как пользоваться

```lua
local data = require('tnt.data')
local json = require('json')

---@class Address
---@field city string
---@field zip string|nil

---@type TntDataShape<Address>
local Address = data.define({
    name = 'Address',
    fields = {
        { 'city', 'string', min = 1, max = 64 },
        { 'zip', 'string', pattern = '^%d%d%d%d%d%d$', optional = true },
    },
})

---@class User
---@field id integer
---@field name string Имя, как его видят в панели
---@field role "admin"|"viewer"
---@field password string
---@field created_at string|nil
---@field address Address|nil
---@field tags string[]

---@type TntDataShape<User>
local User = data.define({
    name = 'User',
    about = 'Пользователь панели',
    fields = {
        { 'id', 'integer', min = 1 },
        { 'name', 'string', min = 1, max = 64, about = 'Имя, как его видят в панели' },
        { 'role', 'string', one_of = { 'admin', 'viewer' }, default = 'viewer' },
        { 'password', 'string', min = 12, hidden = true },
        { 'created_at', 'datetime', as = 'createdAt', optional = true },
        { 'address', Address, optional = true },
        { 'tags', 'list', of = 'string', default = {} },
    },
})
```

```lua
local user, errors = User.from({
    id = 7,
    name = 'Мария',
    password = 'correct horse battery',
    createdAt = '2026-09-19T10:00:00+03:00',
    address = { city = 'Тверь' },
})

user.name                    --> 'Мария'
user.role                    --> 'viewer' — умолчание
user.created_at              --> '2026-09-19T10:00:00+03:00' — в коде имя Lua
json.decode(json.encode(user))
--> { id = 7, name = 'Мария', role = 'viewer', createdAt = '2026-09-19T10:00:00+03:00',
-->   address = { city = 'Тверь' }, tags = {} }
```

Пароля в выдаче нет: он скрытый. Запись — обычная таблица с полями
по именам Lua и метатаблицей формы, у которой `__serialize` — выдача;
поэтому `json.encode`, `msgpack.encode`, ответ по net.box и `yaml.encode`
уносят то же, что `User.to_table(user)`.

Отказ — пара `nil, errors`, как у `tnt-validate`: все отказы сразу, место —
имя **снаружи**, путь до вложенного — через точку и номер с единицы:

```lua
User.from({ id = 0, name = '', createdAt = 'вчера', extra = 1, address = { city = 5 } })
--> nil, {
-->     id = 'должно быть целым числом не меньше 1, а не 0',
-->     name = 'должно быть строкой длиной от 1 до 64 знаков, а сейчас 0 знаков',
-->     password = 'обязательное поле',
-->     createdAt = "должно быть датой со временем и поясом вида ГГГГ-ММ-ДДTЧЧ:ММ:ССZ, а не 'вчера'",
-->     extra = 'неизвестное поле',
-->     ['address.city'] = 'должно быть строкой длиной от 1 до 64 знаков, а не 5',
--> }
```

Ответ 422 из этого собирается так же, как из отказа `tnt-validate`.

### Что есть у формы

| Вызов | Что делает |
|---|---|
| `data.define(spec)` | объявляет форму; негодное объявление — исключение со строкой вызывающего |
| `Shape.from(input, opts)` | запись по форме либо `nil, errors`; `opts.coerce` — приведение строк |
| `Shape.collect(input, opts)` | список записей либо `nil, errors` с местами `[2].name` |
| `Shape.to_table(value)` | выдача: объявленные видимые поля именами снаружи |
| `Shape.annotation()` | аннотация EmmyLua записи текстом |
| `Shape.schema()` | схема OpenAPI 3.0 записи |
| `Shape.name`, `about`, `unknown`, `fields` | объявление, проверенное и разобранное |
| `data.components(shapes)` | схемы форм и всех вложенных — для `components.schemas` |
| `data.annotated(source, shapes)` | `true` либо `nil` и первое расхождение аннотации в тексте модуля |
| `data.described(schemas, shapes)` | `true` либо `nil` и первое расхождение схем документа API |
| `data.KINDS` | роды полей по имени |
| `data.is(value)` | форма ли это — значение `data.define`; им проверяет аргумент тот, кто строит на форме своё — например, белый список полей запроса |

## Объявление

| Ключ | Что это |
|---|---|
| `name` | имя класса аннотации и схемы в описании API; идентификатор, точки разрешены (`Panel.User`) |
| `fields` | поля **списком**, по порядку: `{ 'имя', 'род', настройки… }` |
| `about` | что это за данные — описанием над классом и в схеме |
| `unknown` | лишнее поле во входе: `'error'` (по умолчанию) — отказ, `'drop'` — выбросить |

Поля объявляются списком, а не словарём: порядок виден снаружи — им идут
строки аннотации и обязательные поля в описании API, — а у словаря Lua
порядка нет, и описание переставлялось бы от запуска к запуску.
`unknown = 'keep'`, который знает `tnt-validate`, здесь не бывает: поле,
которого нет в объявлении, в запись формы не попадает никогда.

### Роды

| Род | Проверка | Настройки | В аннотации | В схеме |
|---|---|---|---|---|
| `string` | `validate.string` | `min`, `max` (в знаках), `pattern`, `one_of` | `string`; перечень — `"admin"\|"viewer"` | `string`, `minLength`, `maxLength`, `enum`, `x-lua-pattern` |
| `integer` | `validate.integer` | `min`, `max` | `integer` | `integer`, `minimum`, `maximum` |
| `number` | `validate.number` | `min`, `max` | `number` | `number`, `minimum`, `maximum` |
| `boolean` | `validate.boolean` | — | `boolean` | `boolean` |
| `uuid` | `validate.uuid` | — | `string` | `string`, `format: uuid` |
| `email` | `validate.email` | — | `string` | `string`, `format: email` |
| `url` | `validate.url` | `max` (2048), `schemes` (`http`, `https`) | `string` | `string`, `format: uri`, `maxLength`, `x-schemes` |
| `date` | `validate.date` | — | `string` | `string`, `format: date` |
| `datetime` | `validate.datetime` | — | `string` | `string`, `format: date-time` |
| `any` | `validate.any` | — | `any` | `{}` — годится всё |
| `list` | `validate.list` | `of` (обязательно), `min`, `max` | `T[]` | `array`, `items`, `minItems`, `maxItems` |
| `map` | `validate.map`, ключ — строка | `of` (обязательно) | `table<string, T>` | `object`, `additionalProperties` |
| другая форма | запись этой формы | — | имя формы | `$ref: '#/components/schemas/<имя>'` |

Настройки каждого поля с именем:

| Настройка | Что делает |
|---|---|
| `optional = true` | поле можно не присылать; в записи его тогда нет; в аннотации `T\|nil` |
| `default` | чем заменить отсутствие; поле с умолчанием есть в записи всегда |
| `about` | описание поля — хвост строки `---@field` и `description` в схеме; одна строка |
| `as` | имя снаружи: во входе, в пути отказа, в выдаче и в схеме; в коде поле зовётся своим именем |
| `hidden = true` | поле принимается на входе и не отдаётся на выходе; его значение не показывает и отказ; в схеме `writeOnly` |

Элемент списка и значение отображения — `of`, та же запись без имени:
`of = 'string'`, `of = Address`, `of = { 'string', max = 32 }`,
`of = { 'list', of = 'integer' }`. Общих настроек у элемента нет:
необязательным, скрытым и переименованным он не бывает.

Незнакомая настройка, настройка чужого рода, негодный род — исключение
при загрузке модуля со строкой, где форму объявили:

```lua
data.define({ name = 'Bad', fields = { { 'admin', 'boolean', max = 1 } } })
--> app/data/bad.lua:3: форма Bad, поле admin: ключа «max» нет, есть about, as, default, hidden, optional
data.define({ name = 'Bad', fields = { { 'id', 'int' } } })
--> …: форма Bad, поле id: рода «int» нет, бывают string, integer, number, boolean, uuid, email, url, date, datetime, any, list, map и форма data.define
data.define({ name = 'Bad', fields = { { 'tags', 'list' } } })
--> …: форма Bad, поле tags.of — строка или таблица, а не nil
data.define({ name = 'Bad', fields = { { 'id', 'integer', as = 'key' }, { 'key', 'string' } } })
--> …: форма Bad: имя снаружи key занято полями id и key
```

### Умолчание проверяется при объявлении

```lua
data.define({ name = 'Bad', fields = { { 'role', 'string', one_of = { 'admin', 'viewer' }, default = 'root' } } })
--> …: форма Bad, поле role: умолчание не проходит своё правило — должно быть одним из: 'admin', 'viewer', а не 'root'
```

Без этого умолчание, которого проверка никогда бы не пропустила, тихо
уезжало бы в хранилище: `tnt-validate` умолчание не проверяет, он
подставляет его как есть. В запись идёт проверенное умолчание — у вложенной
формы это запись формы, у `uuid` — строка в нижнем регистре. Таблица-умолчание
копируется на каждую запись, функция зовётся на каждую запись; ответ
функции не проверяется — проверить его заранее нечем.

## Вход

`Shape.from(input, opts)` — запись либо `nil, errors`; `Shape.collect` —
то же для списка. Проверяет `tnt-validate`, и его договор здесь
не меняется: лишнее поле — отказ, `null` из JSON (`box.NULL`) —
отсутствие, строка не в UTF-8 — отказ, путь до места — `items[2].price`.

**Приведение — только по просьбе**, как у `tnt-validate`. Строка запроса
и переменные окружения приходят строками, и `'5'` станет числом только
с `coerce = true`:

```lua
User.from({ id = '5', name = 'a', password = 'correct horse battery' })
--> nil, { id = "должно быть целым числом не меньше 1, а не '5'" }
User.from({ id = '5', name = 'a', password = 'correct horse battery' }, { coerce = true }).id
--> 5
```

Настройка у входа одна — `coerce`; незнакомая — исключение со строкой
вызывающего: «настройки: ключа «coerse» нет, есть coerce». Общий
проверяльщик `tnt-validate` настраивается приложением
(`validate.configure`), и его `coerce` действует и здесь, а обращение
с лишним полем у формы своё — `unknown` объявления.

**Вложенная форма приходит своей записью**: `user.address` — запись
`Address`, и `json.encode(user.address)` отдаёт выдачу `Address`.
Список и отображение форм — записи тоже.

```lua
User.collect({ { id = 1, name = 'a', password = 'correct horse battery' }, { id = 0, name = 'b' } })
--> nil, {
-->     ['[2].id'] = 'должно быть целым числом не меньше 1, а не 0',
-->     ['[2].password'] = 'обязательное поле',
--> }
```

Типы записей видит анализатор: класс записи пишут над формой, а форму
объявляют `---@type TntDataShape<User>`. Тогда `User.from` отдаёт `User|nil`,
и `user.nope` или `user.role = 'root'` — предупреждение `emmylua_check`,
а не находка в бою.

## Выдача

`Shape.to_table(value)` отдаёт таблицу, готовую к JSON и msgpack. Годится
и запись, и любая таблица, собранная кодом, — например, строка хранилища:

```lua
local datetime = require('datetime')

User.to_table({
    id = 7,
    name = 'Мария',
    password = 'x',
    password_hash = 'y',
    created_at = datetime.parse('2026-09-19T10:00:00+03:00'),
})
--> { id = 7, name = 'Мария', createdAt = '2026-09-19T10:00:00+03:00' }
```

- **Только объявленное.** Поле, которого нет в форме, наружу не уходит,
  даже если лежит в таблице: ответ, собранный из записи хранилища, иначе
  унёс бы клиенту всё, что в записи было.
- **Без скрытого.** `hidden = true` — поле входа, не выхода: пароль.
- **Имена снаружи** — те же, что во входе.
- **Пустое поле** — `nil` либо `box.NULL` — не уходит вовсе, а не `null`.
- **Значения Tarantool — записью.** `uuid` — строкой; `datetime` в поле
  `datetime` — записью RFC 3339 со смещением через двоеточие (встроенный
  JSON пишет `+0300`, а `format: date-time` обещает `+03:00`); `datetime`
  в поле `date` — `ГГГГ-ММ-ДД`. Строка идёт как есть.
- **Пустой объект и пустое отображение — `{}`, пустой список — `[]`.**
  Без пометки встроенный JSON закодировал бы пустую таблицу списком
  (документ `tnt-collection`, «Список или словарь в JSON»).

Выдача значения **не проверяет**: форму проверяют на входе, а выдачу
собирает код, и его ошибку ловят его проверки. Проверяется только то, без
чего выдачу не собрать, — и это исключение с местом:

```lua
User.to_table({ id = 7, name = 'Мария', address = 'Тверь' })
--> app/handlers/users.lua:12: User.address — таблица, а не строка
```

`json.encode(record)` с такой поломкой бросает ту же причину без места:
над выдачей стоит кадр кодировщика.

## Аннотация

```lua
print(User.annotation())
```

```
--- Пользователь панели
---@class User
---@field id integer
---@field name string Имя, как его видят в панели
---@field role "admin"|"viewer"
---@field password string
---@field created_at string|nil
---@field address Address|nil
---@field tags string[]
```

Аннотацию нельзя получить из объявления на лету: анализатор типов читает
исходники и кода не исполняет. Поэтому она лежит в модуле текстом — её
печатают `Shape.annotation()` и вставляют над формой, — а согласие
с объявлением держит сверка в проверках модуля:

```lua
local source = io.open('app/data/user.lua'):read('*a')

t.assert_equals({ data.annotated(source, { User, Address }) }, { true })
```

Сверяются строка `---@class` и строки `---@field` подряд за ней. Описание
над классом — текст для человека, его сверка не трогает; отступ и пробелы
по краям — тоже. Отказ называет первое расхождение:

```lua
data.annotated('---@class Address\n---@field city integer\n', { Address })
--> nil, 'аннотация Address расходится с объявлением: ждали «---@field city string», а стоит «---@field city integer»'
data.annotated('---@class Address\n---@field city string\n', { Address })
--> nil, 'аннотация Address расходится с объявлением: не хватает строки «---@field zip string|nil»'
data.annotated('', { Address })
--> nil, 'аннотации ---@class Address в тексте нет'
```

Перечень, который буквальными строками не записать (есть кавычка, обратная
косая черта или перевод строки), в аннотации — просто `string`. Поле
с умолчанием — без `|nil`: в записи оно есть всегда.

## Описание API

```lua
User.schema()
--> {
-->     type = 'object',
-->     description = 'Пользователь панели',
-->     required = { 'id', 'name', 'password' },
-->     additionalProperties = false,
-->     properties = {
-->         id = { type = 'integer', minimum = 1 },
-->         name = { type = 'string', minLength = 1, maxLength = 64, description = 'Имя, как его видят в панели' },
-->         role = { type = 'string', enum = { 'admin', 'viewer' }, default = 'viewer', nullable = true },
-->         password = { type = 'string', minLength = 12, writeOnly = true },
-->         createdAt = { type = 'string', format = 'date-time', nullable = true },
-->         address = { allOf = { { ['$ref'] = '#/components/schemas/Address' } }, nullable = true },
-->         tags = { type = 'array', items = { type = 'string' }, default = {}, nullable = true },
-->     },
--> }
```

Схема говорит то же, что проверка делает:

- обязательные — поля без `optional` и без умолчания;
- `additionalProperties: false` — если форма лишнее поле отвергает
  (`unknown = 'error'`); у `'drop'` ключа нет;
- `nullable` — у необязательных: `null` на их месте проверка читает как
  отсутствие и принимает;
- `writeOnly` — у скрытых: их присылают, но не получают;
- `default` — умолчание в виде выдачи; умолчание-функцию описать нечем.

Две вещи описанию не передать, и они стоят своими ключами `x-`, которые
OpenAPI разрешает. **Образец строки** — образец Lua, а не регулярное
выражение ECMA, которого ждёт `pattern`: `%d` там значит другое, и клиент,
поверивший ему, проверял бы не то. Он уходит в `x-lua-pattern`. **Схемы
ссылки** — в `x-schemes`: `format: uri` их не ограничивает. У ссылки
на вложенную форму соседние ключи OpenAPI 3.0 не читает, поэтому ссылка
с описанием, `nullable` или `writeOnly` завёрнута в `allOf`.

`data.components({ User })` собирает схемы названных форм и всех
вложенных — то, что кладут в `components.schemas` документа:

```lua
print(yaml.encode({ components = { schemas = data.components({ User }) } }))
```

Две разные формы под одним именем — исключение: «две разные формы зовутся
Address». Согласие документа с объявлением держит вторая сверка:

```lua
local document = yaml.decode(io.open('api/openapi.yaml'):read('*a'))

t.assert_equals({ data.described(document.components.schemas, { User }) }, { true })
```

Сверяются схемы названных форм и всех вложенных; прочие схемы документа —
тела отказов, чужие формы — не трогаются. Отказ называет первое
расхождение путём:

```lua
--> nil, 'в описании нет схемы Address'
--> nil, 'описание расходится с объявлением: User.properties.tags.items.type — в описании «integer», в объявлении «string»'
--> nil, 'описание расходится с объявлением: User.required[3] — в описании «nick», в объявлении «password»'
```

## Форма переноса, а не хранения

Запись хранилища объявляют своим средством — формат спейса, индексы,
чтение и запись. `tnt-data` — форма того, что **переносится**: тело
запроса, ответ, сообщение очереди. Это разные формы и тогда, когда поля
совпадают: у ответа нет хеша пароля, у тела запроса нет `bucket_id`,
у записи хранилища нет подтверждения пароля. Слить два объявления в одно
значило бы снова держать одну форму на две заботы — ровно то, от чего
пакет написан.

## Чем пришлось поступиться

- **Аннотация — текстом, а не выводом.** Анализатор кода не исполняет,
  и получить аннотацию из объявления на лету нельзя. Цена — строка
  `data.annotated` в проверках модуля; без неё аннотация снова
  разъедется молча.
- **Выдача не проверяет значения.** Число в поле строки уйдёт числом.
  Проверять выдачу на каждый ответ значило бы платить проверкой входа там,
  где данные собирал свой код; его ошибки ловят его проверки.
- **Образец строки — Lua, и описанию он не передаётся.** `x-lua-pattern`
  клиент читать не обязан; регулярные выражения PCRE2 (`pattern_pcre`
  у `tnt-validate`) форма пока не принимает.
- **Умолчание-функция не проверяется и не описывается.** Её ответ
  известен только на входе.
- **Форма не ссылается на себя.** Поле-родом служит уже объявленная
  форма, поэтому дерево произвольной глубины (узел с детьми-узлами)
  так не объявить.
- **Имя ключа отображения — строка.** Ключ-число из msgpack — отказ,
  а не словарь, который потом не закодировать в ответ.
- **`secret` у поля нет.** Прячет ли отказ присланное значение, решает
  `tnt-validate` по имени поля (`password`, `token`, …), а скрытое поле
  прячется всегда: `{ 'pin', 'string', pattern = '^%d+$', hidden = true }`
  отказывает «должно быть строкой по образцу ^%d+$, а не присланным
  значением». Тайну, которую отдают в выдаче, так не объявить.

## Опасные места

- **Хвостовой вызов уводит место.** `return data.define({ … })` в модуле
  формы снимает кадр модуля, и отказ объявления приходит без строки —
  с именем формы и поля, по которым её находят. Вину показывает
  `local User = data.define({ … })` и `return User` отдельной строкой.
- **Запись кодируется выдачей всегда.** `box.space.users:insert(record)`
  отказывает «Tuple/Key must be MsgPack array»: msgpack кодирует запись
  её выдачей — словарём без скрытых полей, — а спейс ждёт кортеж. Кортеж
  для спейса собирают явно — из полей записи по формату спейса.
- **Скрытое поле живёт в записи.** Выдача и `json.encode(record)` его
  не отдают, но `record.password` в коде есть, и строка журнала,
  собранная из него руками, его унесёт.

## Проверки

Внешней службы у пакета нет, и всё проверяется на исходниках: `test/`,
по файлу на возможность — объявление, вход, выдача, аннотация, описание
API, — грузит модули пакета с диска, мимо загрузчика `.rocks`,
а зависимости берёт установленными. Отказы, аннотации и схемы сверяются
целиком и дословно: текст отказа, аннотация и схема и есть то, ради чего
пакет написан, и «где-то там сказано про поле» их не проверяет. Значения
Tarantool в выдаче — `uuid`, `datetime` — настоящие; кодирование записи
проверяется настоящими `json`, `msgpack` и `yaml`.

```sh
make deps          # luatest, luacheck, luacov с cluacov и tnt-must, tnt-collection, tnt-validate в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants, порог 100 % убитых
```

Покрытие строк — 100 %, убитых мутантов — 100 % (60 проверок, 304 мутанта
в семи модулях).
